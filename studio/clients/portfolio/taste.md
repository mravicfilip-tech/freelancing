# Taste log, portfolio

Filip's own portfolio site (repo mravicfilip-tech/filip-portfolio). Newest entry at the top.
`/taste` writes here the turn Filip picks or rejects a look. The `/uireview` critic and every
builder read this whole file before judging or building, so each entry is a rule. Entries marked
SUPERSEDED are not rules and move to `taste-archive.md` once this file passes 8,000 characters.

Entry format.

```
- **YYYY-MM-DD HH:MM, <thing>, <what happened>.** ACCEPTED | REJECTED. Said: "<Filip's words, under 20 words>". Why: <the reason>. Carry forward: <the rule a builder follows next time>.
```

- **2026-10-06 14:40, contact plate footer with the name (Field.jsx nameTargets dot name, `.cplate__name`, `.cplate__foot`), all treatments.** REJECTED. Said: "I dont like how you did footer redesign it from scratch with my name". Why: the name as a giant dot-field screen read as an LED board, too loud under the ask, and the fainter dot, hollow outline and 7% engraved versions were the same idea turned down rather than a design (inferred). Losers: dot name at alpha 0.95 then 0.45, 1 faint fine dots, 2 hollow outline with fade, 3 engraved. Carry forward: the footer is redesigned from scratch around the name as real type; no dot-field lettering and no full-width watermark name in the footer.
- **2026-10-06 13:05, project window entrance, ?frame=1 trace / 2 print / 3 open.** REJECTED. Said: "the frame transition and animation here is badly executed on all 3 variants". Why: the window chrome arrived as a separate effect on top of the dot hand-off (a line drawing, a second mask, a clip opening), so the plate played two transitions at once and the window looked bolted on (inferred). Losers: 1 trace (SVG edge drawn on, bar fades), 2 print (frame mask running ahead of the image's), 3 open (bar grows from centre, window clips open downward). Carry forward: the window is part of the one dot transition: the dots draw the whole window (bar, pill, stop, edge), and one sweep prints the real window, bar and screen together; no second animation on the frame.
- **2026-10-06 12:10, hollow headline words (`.headline .accent`, `.tq__grid-head b`), outline fade.** ACCEPTED, APP-WIDE. Said: "what you did on platform we can do app wide for the gradient". Why: the hero's 'platforms' outline fading left to right read best; one treatment for every hollow word keeps the accent a system, not a one-off. Carry forward: every hollow (text-stroke) word on every route carries the mask `linear-gradient(90deg, #000 0–15%, rgba(0,0,0,.35) 100%)`; no SVG filter on accents by default (metal treatments only behind ?accent=N).
- **2026-10-06 11:43, project cover browser frame (ShotFrame `.proj__shot`), shown before the dots arrive.** REJECTED (still stands; first fix rejected 2026-10-06 13:05). Said: "I don't like the fact the browser is already preloaded". Why: the window chrome sits finished on the plate while the halftone is still flying in, so the frame gives away the reveal before it happens (inferred). Carry forward: on a project plate the ShotFrame window (bar, border, address pill) must arrive as part of the field's transition, never be on screen before the cover's dots land.
- **2026-10-06 11:43, cover hand-off from halftone to image, variant pick.** ACCEPTED. Said: "reveal 1 best". Why: a single diagonal front reads as the cover being printed through; the dots leave exactly where the image arrives, so nothing stacks into a grey wash. Losers: 2 bloom (a circle opening from the centre), 3 dissolve (dots drop at random while the image un-blurs). Carry forward: covers resolve with the sweep in `src/lib/coverReveal.js` (135deg, band 0.35, 1.1s, linear); dots and image always share one reveal key, and the halftone stays at alpha 0.1 + 0.46·v.
